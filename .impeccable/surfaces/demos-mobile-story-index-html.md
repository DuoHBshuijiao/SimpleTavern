# Mobile story demo

Scope: `demos/mobile-story/`. Visitor mode: Operate. A standalone browser prototype of the Android interaction idea discussed on 29 September, using synthetic characters, stories, and replies. No backend, private data, credentials, or production UI changes. The user asks for a rough, clickable framework, not finished visual detail.

## Direction contract

THESIS: Open into an ongoing story. The composer’s plus expands the people, identity, scene, and goal; history finds the same objects again.

OWN-WORLD: A dark, readable mobile surface for evening reading, with stable teal, amber, and lilac story symbols. Simple system sans, quiet messages, connected chapter rows, one bottom composition sheet. No generated imagery.

STORY: Continue chatting; expand plus; change the combination; preserve or start independent experiences explicitly; inspect story memory; filter and reopen history. Shared character drafts and story memories have distinct places.

FIRST VIEWPORT: A 412-pixel phone canvas with compact story header, scene summary, readable conversation, and bottom plus/input/send row. Desktop adds a short set of preview shortcuts outside the phone. Mobile uses the full viewport.

FORM: The user-pinned story/composition direction from the prior discussion overrides the seed assignment (`8e8e0905`, degraded without challengers). Code-led rough prototype; no concept tournament or raster comps, consistent with the requested scope.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

Exit scope: prove the navigation and primary interactions in the browser. Document only this isolated prototype under `docs/demos/`; preserve the desktop PRODUCT.md, DESIGN.md, and sidecar. Native Android, API requests, durable story architecture, and visual refinement remain outside this demo.

## Result

Finish review: **ship**, scoped to the requested rough interaction framework; no material fixes. Reviewed the 390×844 mobile canvas, 1440×900 desktop preview, and 1042×764 actual browser window, plus composition, history, memory, and first-use captures. The browser walkthrough checked the core navigation, draft return, per-session overrides, story-memory separation, and synthetic send/stop flow. No claim of native Android or backend validation.
