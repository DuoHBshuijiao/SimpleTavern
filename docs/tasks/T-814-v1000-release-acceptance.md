# T-814 v1.000 发布验收清单

状态：**作者已确认范围**（2026-11-07），替代逐项核对。

路线图原定对照 654 个控件和 137 个接口操作逐项黑盒核对，并交给“测试组”。实际只有作者一人，所以这里缩成：能自动的都自动，作者只测真实模型、真实账号和手感。

## 验证原则

作者撤掉测试框架的原因：AI 写完业务代码接着写测试，容易照着答案出题，几百个测试永远是绿的。所以：

- 不写跟着实现走的业务单测。验证靠黑盒：对着接口做正向和负向，在构建产物上驱动界面。
- 黑盒检查由不看实现代码的一方，依据官方文档和 `docs/specs/` 编写。
- 每项检查都要做对照：在修改前的版本上能失败，否则不算数。
- 全绿不等于没问题。回归 125 项全绿时，模糊失效和列表滚不到底都还在。

标记：`[自动]` 回归工具跑；`[Claude]` 在无密钥沙箱里核对；`[作者]` 需要真实账号、真机或手感。

## 放行标准

- 所有 `[自动]` 和 `[Claude]` 项通过，`[作者]` 项全部走完。
- 没有未修的 P0：丢数据、无法生成、泄露密钥、构建后白屏或崩溃。
- P1（主流程出错但能绕过）修掉，或由作者决定写进“已知问题”。P2（外观和小问题）可以放到 1.1。
- “确认”以构建产物为准，开发服务器的结果不算数。
- 候选版本提交后，只有修问题的改动才能进入；每次修改后重跑自动回归。

## 四、作者手测（分三晚，每晚不超过 12 项）

全程用 `npm run build` 后的实际构建。发现问题就记下，不用当场修。

### 第一晚：日常对话（真实模型）

- [ ] 冷启动：运行 `deploy.py`，页面打开，没有报错提示，能进入上次的会话。
- [ ] 单聊流式：常用预设发一条消息，文字逐步出现，结束后用量和耗时正确。
- [ ] 思考模型：思考内容流式显示，结束后收起。
- [ ] 流式中向上滚：能停在原位，回到底部后恢复跟随。
- [ ] 中途停止：内容保留，刷新页面后还在。
- [ ] 断流和错误：填错密钥或断网，提示能看懂、能定位，用户消息不丢，可以重试。
- [ ] 重写和切版本：版本正确，切换时正文滑入。
- [ ] 编辑和删除消息：删除原地确认，刷新后结果正确。
- [ ] 分叉：从中间分叉，新分支内容正确，原会话不变。
- [ ] 进入长会话：停在最后一条开头；搜索能跳转并标出目标。
- [ ] 协议覆盖：用手上有账号的预设，各发一条（OpenAI 兼容、Responses、Anthropic、Gemini）。没有账号的协议在记录里写“未覆盖”。
- [ ] 会话模型面板：切模型、思考深度和 Fast，下一条请求生效。

### 第二晚：数据进出

- [ ] 完整备份：`with_chats` 范围导出，ZIP 能下载。
- [ ] 恢复演练：用空的数据目录（`SIMPLETAVERN_DATA_DIR` 指向新目录）导入这份备份，角色、会话、世界书、记忆、知识图谱、头像都在。**不要在真实 `data/` 上做。**
- [ ] 记录备份里是否含 API Key 和 OAuth 凭据，恢复后要不要重新填，写进 README。
- [ ] 导入角色卡：PNG、JSON 各一张，内容和头像正确。
- [ ] 导入 SillyTavern 聊天和预设，警告能看懂。
- [ ] JanitorAI 导入：通过扩展导入一张卡，空开场白不再变成 “None”。
- [ ] 导出单个会话和角色，能再导回来。
- [ ] 世界书：关键词命中时确实注入（看 HTTP 日志里的请求）。
- [ ] 正文正则：一条规则按预期生效。
- [ ] 完整性巡检：启动提示和设置里的结果可信。

### 第三晚：扩展功能

- [ ] 群聊：新建 2～3 人群聊，轮流发言；成员的思考深度和参与概率（含 0）生效。
- [ ] 插话和旁白：行为符合预期。
- [ ] ChatGPT 订阅登录：登录、发消息、退出，凭据没有写进 `settings.json`。
- [ ] Copilot 和 Codex 或 Grok 登录：有账号的走一遍，没有的写“未覆盖”。
- [ ] 联网搜索：独立搜索一家、模型原生联网一家，来源能看到。
- [ ] 助手：用工具完成一次操作，破坏性工具默认需要开关。
- [ ] MVU 和知识图谱：常用的话各走一遍，不用就写“未覆盖”。
- [ ] TTS：平台一家、本地一家，能合成和播放，切提供商后音色提示正确。
- [ ] 外观：阅读字体、行高、背景透明度和模糊，保存后刷新还在。
- [ ] WebGPU 背景：开关和切预设正常。
