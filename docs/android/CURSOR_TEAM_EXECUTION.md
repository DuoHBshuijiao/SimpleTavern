# Android 核心迁移：Cursor 团队执行约束与交接目标

日期：2026-09-30。本文是给 Cursor 主代理及其子代理的执行任务书。读完后应开始落实代码与验证，不能只再产出一份计划。

**本轮目标：在仓库内完成可构建、可调用、可持久化、能够在 Android 上运行的完整业务底座，让后续 Codex 可以集中开发原生前端。Cursor 不做前端。**

当前起点是需求和源码调查，尚无 Android 导入成功、设备运行或性能达标的证据。本文中的要求、模块名、里程碑都是待实施目标，不能当作完成记录。

## 1. 给 Cursor 的启动指令

请以本文件和同目录 `DATA_REQUIREMENTS.md` 为任务依据，组织一队子代理推进 Android 业务核心迁移。先核对仓库规则、已有改动和真实源码，再确定模块契约与文件所有权，随后并行实施、持续集成并验证。目标覆盖本文全部底层能力，不止工程骨架、接口声明、演示数据或一个最小聊天请求。

前端留给后续 Codex：不要创建或修改 Compose 页面、导航、聊天列表、消息渲染器、设置页、审批弹窗、文件管理器或任何 Demo，也不要修改桌面 Vue 界面。提供这些界面将要调用的业务接口、持久状态和事件流即可。

普通技术细节自主决定，记录原因和影响即可。遇到难点先研究和验证，继续推进不依赖该难点的任务；不得自行删除记忆、降级沙箱隔离、禁止同沙箱并发或改变数据兼容要求。真正无法继续时，留下可构建代码、复现证据和精确交接点，方便回到 Codex 接手。

## 3. 已定产品要求，不重新投票

### 3.1 技术与产品方向

- Android 原生；Kotlin 业务核心、SQLite + Room。将来的 UI 使用 Jetpack Compose，但不在 Cursor 本轮范围内。
- 不复用 Python 业务核心，不嵌入 Chaquopy，不把现有 FastAPI 服务塞进手机，不依赖桌面或局域网服务才能运行核心业务。
- 不以 Flutter、WebView、Vue、Capacitor 或 Tauri 替代原生 UI。当前不做 iOS、PC 体验统一或双向同步。
- 有具体运行时需求才引入 Rust/C/C++；不能先把全部核心拆成多语言。沙箱内用户安装的运行时与 App 的 Kotlin 业务核心是不同层次，不得借此复用旧 Python 后端。
- 普通未 root 手机可用；性能优先。精确 SDK、依赖版本、Android 最低版本等由团队核实兼容性后确定并记录。

### 3.2 用户实际要得到的能力

- 现有桌面数据导入后可继续使用；官方 RikkaHub 备份导入后可找到助手、历史、候选版本、附件、配置并继续聊天。
- 角色扮演必须有真正可用的记忆。长期记忆、自动总结、记忆锚点、上下文注入、MVU 状态、知识图谱均进入本次底层迁移目标，不因实现困难延期。
- 单聊、群聊、角色、Persona、世界书、会话覆盖、消息编辑与分支、助手工具形成完整业务链路。
- 第一版必须具备完整多沙箱；每个环境有完整 shell、依赖环境与读写改工具。仅目录列表、假终端或限定几条命令不能算完成。
- 不准挂外部目录。外部文件只能由用户手工选取并导入副本；不持续同步，不回写源文件，不共享不同沙箱的目录。
- 不同会话允许同时生成；同一会话一次只有一个前台对话生成任务。同一沙箱可以同时执行多个任务。
- 切会话、切后台、锁屏后继续运行；提供后台通知和停止能力。真实可靠性必须用设备验证。
- 停止或中断后保留已保存消息、日志及文件修改；用户最终应能看到实际文件变化。无自动回滚、重放或续跑，也无中断任务的重试、恢复、继续按钮。后续由下一回合提示词发起新任务。
- 工具可设全自动，或分别为 shell、写入、修改设置审批。需要审批的调用逐个排队，用户手动逐项确认。

### 3.3 已批准的延期项与不属于本轮的事项

- 桌面内置聊天助手旧工作区文件的迁移明确延期；助手配置与持久化聊天历史仍须迁移，普通聊天附件仍须迁移。
- 桌面补齐新多沙箱和 Android 新数据格式、双向同步、iOS 均在后续。
- 所有前端实现与最终 UI/渲染验收留给 Codex。底层完成不能宣称“完整 App 已完成”。
- 不把本任务扩大为本地大模型推理、全新云同步平台或全新插件市场。发现来源已有扩展数据时登记并保留，列明运行适配范围。

## 4. 架构交付约束

建议以少量职责明确的模块启动，按需要拆分，不以模块数量衡量进度：

- `core/model`：领域实体、ID、错误、任务状态、协议无关消息与事件。
- `core/data`：Room、附件存储、迁移、查询、事务、备份批次。
- `core/import`：桌面与 RikkaHub 适配器、统一导入计划和报告。
- `core/conversation`：提示词、上下文、单聊、群聊、分支、角色与世界书。
- `core/memory`：长期记忆、总结、锚点、MVU、知识图谱及更新任务。
- `core/llm`：提供商协议、流事件、工具回传、参数、usage 与错误。
- `core/tools`：工具注册、执行、审批策略、审批队列和审计记录。
- `runtime/sandbox`：环境安装、进程、文件边界、文件工具、变化记录。
- `runtime/android`：后台任务宿主、通知停止、生命周期、凭据存储、文件导入适配。

模块路径是责任示例，主代理须在正式开发前固定真实路径。领域逻辑尽量不依赖 Android UI 类型；Android 特有能力通过明确接口接入。不要为不存在的跨端需求建通用框架。

所有界面将来通过公开业务接口获取数据和发起操作，不直接操作 Room 表、沙箱路径或提供商 SDK。接收流、数据库保存和任务调度不能依赖页面是否存在，也不能由页面组合生命周期决定存亡。

必须提供的接口类别：

- 配置与内容：角色、Persona、世界书、助手、模型预设、会话覆盖的查询与修改。
- 消息：分页、候选版本、选中项、编辑、分支、查询；生成/停止与事件订阅。
- 记忆：查看/编辑/更新、总结状态、锚点、上下文构建结果、MVU/图谱读写和日志。
- 导入与导出：预检、计划、执行、进度、取消、失败报告、备份恢复。
- 沙箱：创建/删除/列出/选择环境、导入文件、列目录、读写改、启动与停止进程、输出订阅。
- 审批：策略读写、待办队列、单项批准/拒绝、失效原因及状态订阅。
- 任务：运行列表、终态、已保存结果、文件变更列表、后台状态与取消。

接口规格须写明输入输出、错误、线程/协程约束、状态顺序、持久化位置及取消语义，不能只列函数名。

## 5. 数据与导入工作包

### 5.1 统一存储

- 消息节点、候选版本、当前选中项、附件引用、分支与任务日志独立建模；长历史按窗口读取，不把整段聊天作为每个 token 都重写的大 JSON。
- 配置允许结构化字段与 JSON 扩展体结合；保留未知源字段，但正常业务读取转换后的模型。
- 文件使用 App 内部受管理位置，数据库使用稳定引用；恢复或导入后不能依赖旧绝对路径。
- 高频流写入合并，终态及时保存。明确崩溃时可能丢失的尚未持久化尾部，不能承诺零丢失却没有实现。
- 数据库迁移必须保留用户数据；禁止 destructive fallback、升级失败删库重建或清库掩盖错误。
- 提供完整导出与恢复底层能力，覆盖数据库、普通附件、记忆、配置、沙箱用户文件和环境信息。备份是否包含可重建运行时可分选项，但必须说明依赖重建方式与离线限制。
- 活跃任务下备份需要一致性方案；不能简单复制正在写入的数据库文件就宣称快照完整。凭据包含策略单独定义，日志和诊断包须脱敏。

### 5.2 桌面适配器

先从 `backend/app/storage.py`、`schemas.py`、`routes/import_export.py` 和相关服务生成数据清单，再实现映射：角色及头像、Persona、世界书、消息/思考/工具记录、群聊成员及覆盖、分支、长期记忆、MVU、知识图谱、Assistant 配置与历史、附件、模型与提示词配置、用量等。

当前桌面设置备份 ZIP 并不包含全部持久数据。支持旧包时准确报告缺项；另提供兼容的完整打包入口或离线稳定快照方案。不得把缺附件、缺记忆的旧包称为完整迁移成功。

每类数据登记源位置、版本、目标实体、关联规则、转换损失、可重建性、验收案例。明确排除的旧工作区文件单列待办，不能借该例外排除整个 Assistant。

### 5.3 官方 RikkaHub 适配器

用户使用官方版本，确切版本待补。已调查样本是官方 2.5.5、提交 `6c903feba7e6b65f518b320a88ae29efebae77c4`、Room schema 25；这不是用户实际版本的确认，也不是可硬编码的唯一格式。

- 按来源 schema 和备份结构识别；处理设置、数据库与文件可选的备份形态，以及旧 WAL 相关情况。
- 来源数据库在暂存副本中读取；不得替换 App 自己的活动数据库。
- 保留助手/会话关联、所有消息候选及选中项、思考、附件、工具记录、模型配置、提示词、记忆与世界书。
- 路径/URI 转换为导入后的受管理引用；无法迁移的凭据要求后续界面明确重新配置，不输出密钥。
- 对来源工具、skills 或环境数据逐项确认结构与用途；导入过程不执行包内脚本或自动安装不明内容。
- 不支持的 schema 明确报告；版本未补充不妨碍按可获取官方样本和合成包实施，但“用户备份验证”必须保持未验证。

### 5.4 通用正确性

同包重复导入无重复；来源变化不覆盖 App 内用户新编辑；ID 冲突统一映射。附件、数据库和导入批次共同管理，失败保留旧数据，取消与重启可识别未完成批次。检查归档路径和展开大小，拒绝跨目录写入。报告区分已转换、仅保留、缺失、失败与明确延期。

## 6. 聊天、记忆与角色扮演工作包

### 6.1 聊天与提供商

- 实现单聊及群聊调度、成员级设置优先级、单次插话、停止、消息编辑、候选版本与分支语义。行为从现有实现核对，不只搬字段。
- 群聊调度放入持久任务层，不能依赖未来页面停留。群聊内部多个成员请求属于同一轮调度，不能与其他用户生成入口重复抢占同一会话。
- 支持现有主协议类别：OpenAI-compatible、OpenAI Responses、Anthropic Messages、Gemini。逐协议核实官方字段与流格式，不能把所有协议伪装成 Chat Completions。
- 覆盖思考、工具调用往返、多模态附件、错误、取消、usage、缓存信息及参数覆盖；不支持的能力显式报告，不能静默换模型、协议或供应商。
- 现有鉴权/预设/搜索/用量功能逐项建立支持清单。OAuth 和提供商专属功能按 Android 条件适配；不能以保存字符串代替可运行支持。
- 请求、工具与结果通过稳定标识关联。已产生副作用的工具不因网络重连、流重订阅或进程恢复而再次执行。

### 6.2 记忆必须运行起来

以下都需要真实实现和证据：

1. 导入的长期记忆可以查询、编辑、持久化，并实际进入下一轮模型上下文。
2. 手工触发总结与按配置自动总结；保留总结覆盖范围、来源消息、版本、状态和失败原因。
3. 记忆写入与锚点关联一致；只有成功保存后才能推进相应记忆覆盖边界，失败不得悄悄丢弃原上下文。
4. 长上下文预算同时考虑提示词、世界书、记忆、状态与最近消息。不能机械截断导致关键设定全部消失；token 估算不可用时显式记录采取的策略。
5. 总结期间继续聊天、手工编辑记忆或产生分支时，使用版本校验等方式防止过期结果覆盖新内容。不要靠全局禁止并发解决。
6. 会话、角色和来源数据的作用域明确，不把各助手或会话记忆全部合成一份；分支后的继承/重置行为核对现有规则并记录。
7. MVU 状态定义、变量更新、模型任务、工作日志及 RP 上下文注入完整连通。
8. 知识图谱实体、关系、来源和更新真实落库；工具校验引用并参与上下文构建。图谱布局与可视化留给 Codex。
9. 重启后可继续读取与更新，查询及编辑接口完整。提供脱敏的上下文构成诊断，能够证明使用了记忆，不能仅凭模型回答声称“记住了”。

不要以新增向量库或 RAG 框架作为记忆完工前提；先保证现有产品记忆机制完整迁移，再按真实需求优化。总结/MVU 等内部任务与用户对话任务分别标识，但必须遵守同一会话的数据版本和取消规则。

### 6.3 其他底层功能的覆盖深度

世界书触发、顺序与配置覆盖、正文正则、网络搜索、助手专用工具、用量和成本、消息全文检索都进入本轮核心覆盖清单。TTS 的配置、可复用云端调用与播放数据接口可以继续推进；桌面本地 TTS 进程和平台专属能力逐项记录适配边界，不能成为聊天或记忆启动的硬依赖。

原生主题、排版、动画、图谱渲染、音频控制界面均留给前端阶段。来源已有的字体/背景等资源可保留与导出，不为它们实现页面。

## 7. 多沙箱与文件工作包

### 7.1 先解决真实性，再铺开工具

优先做未 root Android 的最小运行验证，记录设备、系统版本、ABI、安装路径、执行机制、进程模型、边界与限制。PRoot/rootfs 是候选，不是已选定或已证明隔离的方案；核实 Android 执行限制、依赖分发、许可证、运行成本和后台行为。

至少两个沙箱的用户文件、可变依赖和环境配置独立。只读公共运行时能否复用由实现决定，但不能因此暴露其他环境的用户数据。明确必要系统/运行时文件的访问范围。

必须验证相对路径跳出、绝对路径、符号链接、进程继承的句柄及运行时可能暴露的宿主路径。工作目录、提示词、工具路径检查都不能单独充当完整 shell 的访问隔离。若候选方案达不到要求，必须留下失败证据并继续评估；不能悄悄把要求改为“请模型不要访问”。

不要求 Docker 式进程/网络/资源强隔离，但文件访问边界依然必须成立。没有成立的证据就不得标记多沙箱验收完成。

### 7.2 运行和文件操作

- 支持正常 shell 语法、管道、重定向、脚本、子进程、退出码、stdout/stderr、取消与有限输出缓存；对大输出采用文件日志或分段读取，避免无限堆内存。
- 环境内可管理所需依赖，重启保留用户文件与安装状态；文件工具和 shell 使用同一环境与权限边界。
- 同一沙箱多任务可同时执行，各自进程、cwd、环境变量、输出和取消状态独立。停止一个任务不能杀掉其他任务。
- 会话与沙箱独立存活，多个会话可以选择同一沙箱；运行中的任务固定关联，切换选择不能把正在执行的命令转到另一个环境。
- 外部文件通过显式调用导入副本；实现输入流/URI 的平台适配、目标选择、重名处理、进度和取消。不申请持续目录挂载权限，不建立外部目录链接，不回写来源。
- 普通附件不会自动变成所有沙箱可读；需要使用时复制进指定环境。不同沙箱之间复制也应是明确操作，不是共享目录。
- 内部环境组装所必需的运行时映射不等于允许产品挂载外部目录；必须保持上述数据边界。

### 7.3 真实文件变化与冲突

同时记录专用文件工具与 shell 造成的新增、修改、删除及可确认的重命名。至少提供路径、变化类型、观测时段、可用的前后摘要和关联任务；无法确定的归属/重命名明确标为未知，不能根据模型文本生成变更清单。

任务停止或异常中断后，已采集记录仍可查询；恢复时可补充环境差异并注明来源。漏采或崩溃窗口须明确表达为记录不完整，不得报告“没有修改”。

同一沙箱并行任务的文件变化可能交叠：区分工具可确认的操作与环境级观测，不伪造精确归属。专用编辑工具使用预期内容/版本校验，冲突时返回实际状态；任意 shell 写入的覆盖风险和可观测边界要如实记录。不能把任务级串行化作为并发问题的最终解法。

## 8. 工具审批、任务和后台工作包

### 8.1 审批服务

- 策略至少支持全自动及 shell、write、edit 三类分别审批；具体默认值由团队选择并写入决策记录。新增工具必须登记类别，不能遗漏删除、重命名、覆盖等变更入口。
- shell 调用中的文件副作用由 shell 类别控制；不要声称能仅靠命令文本分析完整拆解所有效果。全自动 shell 与需审批 edit 的组合含义必须在接口契约中说清楚。
- 只读文件工具不能隐式执行脚本或写文件；任何工具内部派生 shell 也必须走执行策略，避免包装工具绕过 shell 审批。
- 每次审批绑定不可变的调用 ID、会话、沙箱、完整参数和必要的编辑前提。等待批准期间无调用副作用。
- 提供逐项 FIFO 队列、批准、拒绝、失效和待办计数；不实现一键批准全部、记住本轮批准或超时自动批准。
- 默认每会话独立排队，避免一个会话卡住其他会话；同沙箱任务仍允许并发。审批顺序和执行依赖分别管理。
- 变更参数/目标后必须形成新审批；文件编辑的前提过期时报告冲突。重复确认幂等，批准最多触发一次执行。
- 停止任务使尚未执行的审批失效；进程重启后旧未完成任务记中断，旧审批不得继续执行。
- 拒绝作为明确工具结果返回。不能自行换入口重试同一被拒操作来规避用户决定。

Cursor 只实现状态、队列和接口，不实现审批 UI。用底层调用和运行记录验证“未批不执行、逐项批准、拒绝无副作用”。

### 8.2 任务状态与持久化

由主代理统一定义状态机，至少表达排队、运行、等待审批、停止中、成功、失败、已停止、已中断。每个状态明确允许的操作和终态原因；不要各模块各造一套互不兼容的状态。

同会话单生成约束由任务层执行，不能只靠按钮禁用。群聊和助手入口的冲突规则必须一致。内部记忆任务明确单独身份与数据写入规则，避免冒充第二个对话生成任务。

事件须有稳定关联、可去重顺序及持久快照；页面订阅恢复只恢复展示，不重新发起请求或工具。终态和已保存结果一致，生成成功不能掩盖后续记忆任务失败。

显式停止取消网络和任务自己的执行树，保留已产生文件变化。进程退出后的未完成任务标为中断；不得自动恢复网络生成、重放 shell 或执行旧审批。提供下一回合可读取的状态、结果、文件变化摘要与不确定项。

这里的禁止重试针对旧任务及其副作用重放；正常的新回合仍可执行用户新指令。任何未来消息重写能力都不得隐式恢复旧工具队列。

### 8.3 Android 宿主

实现必要的 Android 应用/服务壳、清单、后台生命周期和系统通知停止 action；这些是平台运行能力，不是开发业务前端的许可。除系统运行所需的通知外，不做页面、弹窗或调试面板。

核对当前 Android 官方后台限制并记录策略。切会话不会影响运行；后台/锁屏持续执行要在设备上观察。等待审批时可以发待办通知并暴露未来导航契约，具体审批页面留给 Codex。

可交付库/AAR及无业务界面的最小调试宿主，提供手工诊断入口与命令说明。诊断入口必须限定调试构建，不能给正式版本留下任意执行接口。若某项最终验证依赖真实界面，则准确交接，不能为此擅自做前端。

## 9. 性能与资源要求

本轮完成接收、解析、持久化、查询和后台执行侧的性能工作。Compose 帧率、Markdown 排版、滚动和动画由后续前端阶段完成，Cursor 不写渲染实现。

- 网络接收与事件落盘不依赖 UI 订阅者；没有页面订阅时不做展示加工。
- 向未来 UI 提供消息增量/版本及稳定历史窗口，支持合并通知和按需查询。不能每个 token 都重建或发送整份会话、整篇长思考。
- 慢消费者和订阅取消不应阻塞模型接收或造成无界缓存；结束、错误、工具调用等关键事件不能被粗暴合并丢弃。
- 手工测量合成 1 万条历史、单条 1 万/5 万/10 万字符、多个会话并行流及同沙箱并发；记录输入速度、设备、CPU、峰值内存、写入耗时、查询延迟和日志增长。
- 这些规模是初始验证场景，不是用户数据上限。团队根据实测设性能预算和改前/改后记录，不得只凭换数据库宣称更快。
- 骁龙 8 Elite 是用户已提到的设备平台。未连接到该实机时不要用桌面跑分替代手机结论；留下可复现采样流程。

## 10. 团队分工与协作契约

由 Cursor 主代理负责协调；根据实际可用人数合并角色，不要求同时启动固定数量。每次派工必须写明唯一文件/模块所有权、依赖接口、交付清单和验收方式，并告知子代理“不是独占代码库，不得回滚他人改动”。

- **主代理 / 集成负责人**：工程配置、公共契约、依赖方向、共享 Gradle 文件、状态机、决策记录、合并构建和最终交接。关键公共文件由其单独负责。
- **存储与导入代理**：Room、附件、备份恢复、双来源导入、迁移映射及错误恢复。职责范围不包含提供商或页面。
- **聊天与协议代理**：LLM 协议、提示词、群聊、角色/世界书、消息分支、用量与搜索；与记忆代理通过统一上下文契约衔接。
- **记忆代理**：长期记忆、总结、锚点、MVU、知识图谱与来源版本；须交付运行链路，不止模型定义。
- **沙箱代理**：Android 执行可行性、文件边界、环境管理、进程并发、文件工具和变化观测。首先暴露隔离可行性结果。
- **任务与审批代理**：任务宿主、通知停止、审批服务、任务持久化和中断恢复标记；不创建任何界面。
- **只读验收/交接代理**：按规格核对公开行为、遗漏和证据；发现问题回交对应责任人，不跨模块悄悄重写。仓库外黑盒验证只依赖公开规格，不读取实现源码。

先共同固定 ID、消息事件、任务/审批状态、repository 接口、文件变更记录和错误模型，再进行独立模块实现。单个代理不得擅自改变公共契约；需要变更时提交给主代理统一更新消费者。

每日程或每个实际工作批次结束前集成一次可构建版本。不要让所有代理长期各自宣称完成，最后才发现接口对不上。临时 stub 可用于独立编译，但必须列入未完成清单，不能通过返回空列表/假成功掩盖缺失。

## 11. 推进里程碑：内部阶段，不是缩减目标

### M0：接管与工程契约

产出真实工作区清单、功能覆盖清单、模块所有权、Gradle 工程、构建说明及公共接口初稿。明确哪些是现有行为、哪些是 Android 新功能。建立沙箱可行性任务并立即开展。

### M1：存储、记忆和基础请求贯通

在无前端条件下，完成合成桌面/RikkaHub 输入 → Room → 读取历史和记忆 → 构造包含记忆的上下文 → 接收响应 → 持久化 → 重启读取。只使用合成内容或明确获准的数据，不因缺用户备份而停工。

### M2：完整角色扮演与双来源迁移

完成导入清单、消息版本/分支、角色/Persona、世界书、群聊、长期记忆更新/总结、MVU/知识图谱、多协议与助手工具。核对各来源真实能继续使用的配置，输出不支持项而不是静默丢失。

### M3：完整沙箱与后台任务

完成两个以上独立环境、完整 shell、文件工具、手工导入、同沙箱并行、分类审批、真实变化记录、后台执行和中断处理。隔离不成立或审批可绕过属于未通过，不得用文案解决。

### M4：迁移和运行可靠性收口

覆盖重复/失败/中断导入、数据库升级、备份恢复、取消、并发冲突、记忆版本竞争、大历史与大输出性能、任务和审批重复调用；补齐公开规格与运行证据。

### M5：可交给 Codex 的完整底座

所有本轮底层功能都有真实实现、可调用接口、构建产物与对应证据；无已知导致数据损坏、越界文件访问或重复副作用的阻断问题。提交完整交接包，Codex 能直接接业务接口做原生前端。

M1 结束不能作为整项任务完成。M2 和 M3 可在契约稳定后并行。缺设备/备份/凭据时继续做其他阶段，最终把受阻验收独立列出，不降低原定目标。

## 12. 验收方法与完成判定

遵守仓库现有规则：不新增或运行 pytest、Vitest、Playwright 或其他仓库内自动化测试框架、断言及门禁。Android 也不以更换框架名称绕过该规则。允许实际构建、静态检查、手工诊断、设备运行、性能采样和逐项黑盒核对；自动化黑盒如需要，应由仓库外团队按公开规格实施。

团队须记录实际使用的 Gradle 构建/静态检查命令、JDK/SDK 版本、产物路径及结果。仅改 Android 不需跑桌面前端构建。没有执行的命令写为“待执行”，不能复制别人的成功记录。

每项验收至少记录：环境、输入、操作、预期、实际结果、证据路径、限制。重点场景：

- 双来源导入：完整包、仅设置、缺附件、损坏、ID 冲突、重复导入、取消/重启、已有用户新编辑。
- 记忆：旧记忆进入真实请求上下文；总结成功与失败；并行新消息/手工改记忆；分支不串用；MVU/图谱更新后下一轮可见。
- 沙箱：两个环境分别装依赖和写文件；越界/链接访问；外部源文件导入后独立；取消不误杀其他任务。
- 审批：全自动、各类别组合、逐项确认、拒绝、双击、参数变化、前提过期、后台等待、停止/重启失效。
- 生命周期：不同会话并行、同会话竞争、同沙箱并行、后台/锁屏、手动停止、进程退出后中断，旧命令无重放。
- 变化记录：文件工具、shell、子进程、删除、重命名、大文件、并发归属不明、崩溃窗口。
- 数据恢复：升级、备份还原、附件一致性及沙箱用户文件恢复，不破坏原数据。

状态必须区分“未开始 / 实现中 / 已实现待构建 / 构建通过待运行 / 已运行验证 / 受阻”。保存了字段、接口能编译、单个协议通了，都不等于功能完整可用。不得用一个总百分比掩盖必备功能缺失。

前端接入、最终 APK 的交互验收和长思考实际帧率是后续 Codex 阶段的工作；Cursor 明确交接这些项目，不能宣称通过。

## 13. 必须留下的交接文件

由团队在 `docs/android/` 维护下列文件；内容可以按规模合并，但信息不可省略：

- `IMPLEMENTATION_STATUS.md`：逐功能的实现/构建/运行状态、责任模块、缺口和下一步；当前版本事实来源。
- `CORE_API.md`：未来前端调用的完整业务接口、事件顺序、错误与例子，特别是审批和中断行为。
- `DATA_MAPPING.md`：桌面/RikkaHub 源字段、目标、关联、损失、支持版本及样本来源。
- `DECISIONS.md`：模块、运行时、依赖、默认策略、沙箱边界、后台策略及理由；区分事实与假设。
- `ACCEPTANCE.md`：可供仓库外团队使用的黑盒规格与手工核对步骤，不依赖阅读源码。
- `VERIFICATION.md`：实际构建、设备、协议、导入、性能及失败证据；明确未验证项。
- `CURSOR_HANDOFF.md`：最后可构建状态、变更文件、启动方式、产物位置、已知问题、Codex 应从哪里接手，以及可复制的中文手动提交命令。

交接必须回答：已经完成哪些真实能力；哪些只有声明/样例；哪些被什么外部条件卡住；失败如何复现；下一位需要修改哪些模块。不要只写“剩下优化”和“接前端即可”。

不要把 Android 的阶段成果改写成桌面版本已发布。保留本文件与需求基线作为约束，状态文件记录实际进度，不用修改目标来制造完成率。
