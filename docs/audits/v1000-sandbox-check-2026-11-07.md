## 四、发现的问题

按放行标准分级。P0 没有发现。

**P1-1 设置备份含明文 API Key。** 三种范围的备份里，`settings.json` 都带着全部预设的 API Key。复现：设置 → 外观与数据 → 下载备份（或 `GET /api/settings/backup?scope=basic`），解压后看 `settings.json` 的 `apiPresets[].apiKey`。备份是要能完整恢复，还是要在 README 里写明“备份含密钥，不要分享”，需要作者决定。清单第四节第二晚已有“记录备份里是否含 API Key”一项，这里给出结论：含。

**P2-1 搜索跳到没渲染过的区域后，目标会漂开。** 复现：进入 320 条以上的会话，搜一个命中 300+ 的词，点结果卡片中第 101 或 151 张。第一次采样（250 ms）时目标在开头（误差 1 px），之后约 0.5 秒内漂到 +113～+125 px 或 -14～-25 px 并停住。去过的区域（第 6、第 300 张）不漂。目标仍在视野里，高亮也对。开发和构建都有，修改前的 `ee7b396` 也有。现有的“远距离跳转定位准确”在 0.45 秒采样，赶在漂移之前，所以一直是绿的。

**P2-2 上游回显非 `sk-` 格式的密钥时，HTTP 日志的 `error` 字段留下明文。** 复现：模拟上游返回 401，错误信息里带上收到的密钥（`sandbox-dummy`），之后看 `data/http_log/*.jsonl` 和 `GET /api/http-log`。`sk-…` 格式会被脱敏，其他格式不会。日志只保留 30 分钟，只在本机。真实上游会不会原样回显密钥没有验证。

**P2-3 五个主题的主按钮白字对比度低于 4.5。** green 3.26、teal 3.25、amber 3.21、rose 4.29、sunset 3.02；blue 5.37、violet 4.51。截图上能读，sunset 最浅。门槛 4.5 用的是 WCAG 正文标准，是否采用由作者定。

**P2-4 420 宽选完会话后侧栏不收起，聊天区被推到窗口外。** 复现：窗口 420×800，在侧栏点角色和会话。输入框、发送、搜索的中心点都在窗口右边外面，要手动点“切换侧边栏”。收起后布局正常。这是否是有意的窄屏行为，需要作者判断。

**P2-5 发送时会话已被删掉，页面抛出未捕获的 `ApiError: chat not found`。** 复现：打开一个会话，在别处（或用接口）删掉它，再发送。错误栈正确显示了 requestId，用户的话留在输入框；同时控制台多一个未处理的 Promise 拒绝。

**P2-6 两种流式错误的提示不准。** 上游在流里发 `{"error":{"message":…}}` 时，界面显示“上游流事件缺少 choices”，上游自己的错误信息没有显示；发到一半断连接时显示“无法连接上游服务”，实际已经连上并收到了半句。两种情况下半句都保留了。模拟用的是常见的 OpenAI 兼容格式，没有对照具体厂商的真实流。

**P2-7 单聊出错后没有直接重试的按钮。** 见第三节第 4 项：要编辑最后一条用户消息再“保存并发送”。不算丢数据，属于易用性问题。

### 已有检查的现象（主会话在查，这里只给数值）

- `first_load 没有跑完`：两次全量运行都出现，`TypeError: Cannot read properties of null (reading 'scrollRef')`，即首个页面打开 2.5 秒后 `messageListRef` 仍是空的。它总是全量运行里的第一项。
- `进入时不闪结尾`：两次全量运行都是 `[-3110, 76, 76, 76, 76, 76]`，第一帧最后一条在 -3110 px，之后都在 76 px（等于顶部内边距）。-3110 和修改前的 `a1df022` 在构建上“贴底”时的位置完全相同。新加的 DOM 版本在同一位置采样“画完之后”的帧，开发和构建都没有量到 -3110；它在 rAF 回调里量也没有量到。没有找到原因，不下结论。
- 其余已有检查在两次全量运行里都通过（基线 124 项失败 2；本分支 330 项失败 13，新增的失败都已列在上面）。
