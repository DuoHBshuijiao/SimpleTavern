# 桌面前端设计评审 2026-11-24

这轮走查覆盖桌面工作区、侧栏、聊天输入区、消息结构、设置抽屉、聊天助手设置和角色编辑。首要问题是侧栏的键盘选择和标题空间、低窗口下模型面板裁切、长草稿的滚动反馈、设置草稿被局部动作提前保存，以及新建角色导出失败。深浅色共用信息层级和交互语义，焦点、表面和主按钮按各主题的实际渲染验收。

使用当前工作区的生产构建在 Chromium 中走查。主界面以 1440 × 900 为主，补看 1100 × 700 和 1100 × 450，弹窗取样为 1440 × 1000。主题主样板为青碧，背景透明度设置为 30%，使用工作区的两张壁纸与本地样例数据。助手空态图标另用亮色雾玫瑰对照。界面尺寸为 CSS px，对比度为所述样例和位置的取样值。Windows 原生窗口、系统缩放和强制颜色需在后续验收复核。

## 评审标准

- **信息层级。** 这是长时间使用的工具界面。按 Impeccable 的 Operate 原则，常用任务、状态与控件优先可辨，玻璃和壁纸为阅读让出稳定底色。 [产品说明](../PRODUCT.md) · [设计系统](../DESIGN.md)
- **间距和对齐。** 同类标题和行内容各有固定左轴，同类动作在同一列。控件内部参考 4–8 px，同组间距 12–16 px，独立分组约 24 px。 [项目亮色规范](../specs/DESKTOP-LIGHT-THEME.md) · [Carbon 间距](https://www.carbondesignsystem.com/building-blocks/foundations/spacing/overview)
- **文字与图标。** 先看到名称、正文或当前值，再看到元数据。图标与点击区域分别定尺寸。分支、转群聊等含义复杂的动作配可见文字或清晰的菜单项。 [Carbon 图标](https://www.carbondesignsystem.com/building-blocks/foundations/icons/guidelines)
- **颜色与键盘。** 主题色集中用于主操作、当前项和需要强调的状态。普通文字以 4.5:1 为验收线，辨认控件和状态所必需的非文字图形以 3:1 为验收线，按实际合成背景核对。焦点、悬停和选中能同时区分。 [Material 3 色彩角色](https://m3.material.io/styles/color/the-color-system/) · [WCAG 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) · [非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) · [色彩使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) · [键盘操作](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)

## 深浅主题的焦点表现

用户的三张补充截图分别显示亮色下拉触发器右上角的圆点、暗色关闭按钮的青色描边、亮色关闭按钮右上角的圆点。先前输入区也复现了这个差异，亮色文本区只有右上角点标，暗色文本框和外卡片各画一层焦点效果。

- **初次走查。** 亮色用 6 × 6 px 实心圆点表示键盘焦点，暗色用 2 px 主题色轮廓。同一个关闭按钮在切换主题后改变了焦点形态。暗色聊天输入框和外层卡片还同时显示了两层焦点反馈。
- **修订后的规则。** 深浅色共用单层 2 CSS px 焦点轮廓，同一控件的形状和位置一致，颜色随主题调整。聊天正文输入框由可编辑区域承载焦点，方向键在下拉内移动时轮廓随候选项移动，勾选保留已选状态。 [基础焦点样式](../../frontend/src/styles/base.css#L115) · [项目焦点规范](../specs/DESKTOP-LIGHT-THEME.md#5-组件与状态) · [WCAG 可见焦点](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)
- **验收场景。** 对照下拉、关闭按钮、主输入区、列表项和单选组。用 Tab 与 Shift+Tab 追踪焦点，确认方向键移动到可见候选、Enter 提交、Esc 只关顶层并回焦。另核对滚动裁切、控件缩放、强制颜色和鼠标点击后的焦点表现。补充截图确认的是焦点视觉反馈，完整的键盘路径按各控件分别验证。 [W3C 焦点遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)

## 侧栏

- **会话标题空间和对齐。** 在宽 320 px 的侧栏里，单聊标题起点距左缘 59 px，两条群聊分别为 73 px、87 px。长单聊标题约有 118 px，长群聊约有 88 px。会话行尾的透明按钮仍占宽，角色行悬停则会直接盖住长角色名。建议固定头像槽与标题轴，行尾用一个「更多」菜单，长标题在悬停和聚焦时可看全。 [侧栏历史行](../../frontend/src/components/chat/ChatSidebar.vue#L487)
- **键盘与图标。** Tab 实测会到新建、编辑、删除，跳过身份、角色和会话选择行。单聊里的重命名、删除按钮还被标成群聊。为整行提供键盘激活和当前项语义，低频动作留在独立菜单。用分支图标表示创建分支，转群聊保留文字。 [侧栏选择行](../../frontend/src/components/chat/ChatSidebar.vue#L391)
- **间距与可视面积。** 「我的身份」「角色列表」标题距左缘 17 px，「历史会话」为 13 px。两个「+ 新建」的右边缘相差 10 px。1100 × 700 时，两条身份仍占 185 px，当前单聊在历史区底部仅露半行。建议段头共用约 16 px 横向内边距，低窗口压缩身份区，优先把当前会话完整带入视野。
- **颜色。** 暗色「新建会话」白字约 3.25:1，「+ 群聊」约 3.85:1，选中群聊标题约 4.0:1。亮色「新建会话」约 7.74:1，白色折叠箭头在两张壁纸上的取样约 2.5–2.6:1。亮色青碧可保留 `#205A65` 主色和 `#E0E8E9` 选中底。暗色候选为 `#58C4D8` 实底配 `#0D1518` 深字，实色样板约 9.06:1。折叠箭头用稳定的导航底色。群聊类型用图标表达，当前会话统一用主题色和选中标记。亮色角色行悬停底比选中底更深，独立选中标记也能解决这个歧义。

## 消息结构

- **正文扫读。** 样例中的日期粗体正常，列表标题却露出 `**`。项目的 Markdown 渲染器可复现 `**标题：**正文` 原样显示，`**标题**：正文` 可正常加粗。用户截图只提供渲染结果，原文空格位置需另查。生成端使用稳定格式，中文标点、历史消息与流式结束用黑盒样例检查。样例的 16 px 正文与 28 px 行高可读，增加条目间隔和标题强调优先于整体加大行高。 [CommonMark 加粗规则](https://spec.commonmark.org/0.31.2/#emphasis-and-strong-emphasis) · [项目渲染器](../../frontend/src/utils/markdownIt.ts#L16)
- **来源辨认。** 来源按完整 URL 去重，同站不同文章会显示成同名卡片。样例里正文引用和页脚卡片可指向同一 URL，省略号还可单独换行。正文保留就近引用，页脚默认显示「来源 · N 篇」。展开后用可信标题加站名区分文章，缺标题时用站名加编号。 [来源提取](../../frontend/src/utils/markdownIt.ts#L84) · [来源卡片](../../frontend/src/components/chat/MessageWebSources.vue) · [WCAG 链接用途](https://www.w3.org/WAI/WCAG22/Understanding/link-purpose-in-context.html)
- **结果状态与诊断。** 「缓存命中 4096」为 10 px，缺单位。输出长度上限、Fast 未生效和缓存数据原先在同一行，版本切换另占一行。现把输出长度上限放在正文末尾，版本和重写放在同一组。工具栏同排用纯文本显示「XX 上下文  已缓存 XX」。
- **署名、页脚与操作。** 初次走查中，壁纸上的浅色署名约 3.2:1，缓存字约 3.6:1。现在以署名、正文和首个操作按钮的文字起点对齐，署名直接显示在消息上方。操作胶囊保留原有圆角与尺寸，悬停显示，删除保留确认。 [消息正文与页脚](../../frontend/src/components/chat/MessageList.vue#L1799)
- **阅读顺序。** 署名和可折叠思考 → 正文与就近引用 → 必要的结果状态 → 一行来源、版本与操作。状态标记和链接保持歧义最小的可见文字。

## 设置抽屉

在生产构建中走查全局设置、API 预设和当前会话。青碧主题覆盖 1280 × 900 深浅两色，补看 1100 × 515 暗色和 420 × 770 亮色。保留三个顶层入口、固定页脚、即时外观预览及放弃草稿确认。它们为定位范围和试调外观提供了基础。

### 导航、焦点与保存

- **局部动作提前提交会话草稿。** 样例中填写会话提示，点击「恢复完整上下文」，抽屉保持打开，提示词已经写入。该动作和「从已存记忆处截断」共用整份会话覆盖的保存路径。让两项只更新草稿，随页脚统一提交。如果保留立即执行，只提交对应字段并在动作旁说明。页脚可就近提示哪些范围有未保存修改。 [局部动作](../../frontend/src/components/SettingsDrawer.vue#L1851) · [提交路径](../../frontend/src/components/SettingsDrawer.vue#L4008)
- **不可见字段抢焦点，页签切换携带滚动位置。** 四种尺寸下，从折叠的「连接与默认模型」按 Tab 都进入隐藏的「流式传输」。顶部页签使用普通按钮，右方向键不会移动焦点。短窗口从全局底部切入 API 预设时，内容保留约 494 px 滚动位置。折叠内容应退出键盘顺序，各标签页应独立记忆滚动位置，首次进入从顶部开始，顶部导航采用标准标签页语义与键位。 [折叠容器](../../frontend/src/components/settings-drawer/SettingsDrawerGlobalAccordion.vue#L28) · [顶部导航和共用滚动容器](../../frontend/src/components/SettingsDrawer.vue#L4399) · [W3C Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)
- **固定页脚的位置正确，视觉状态不足。** 未修改与已修改时「保存设置」同样醒目，页脚没有草稿状态。青碧主题保存按钮白字亮色为 7.74:1，暗色为 3.25:1。为暗色主按钮使用适配的前景色，并核对普通字号的 4.5:1。短窗口加强滚动条可见度并避免导航切换落在表单中段。 [WCAG 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

### 全局设置

- **分组标题像功能目录。** 「连接与默认模型」展开后先看到对话模式和思考，默认连接在后。把默认模型及其生效连接提到组首，把协议、回传和供应商参数留在相关的高级区。「网络搜索」选供应商原生时仍和第三方配置一起出现，可把第三方表单收在对应分支。TTS 的前置说明给出直达 API 预设的入口。
- **外观主任务被高级背景打断。** 用户要换深浅色、色系或字体时，要先经过背景图、WebGPU、预设和帧率。把「界面与字体」提到外观开头，壁纸其次，WebGPU 收到高级背景。关闭着色器时可保留已配置摘要，展开后再配置。将备份与导入独立成组，导出按钮写清所含范围。「应用与更新」先露出用量与成本，版本和更新在下方，入口命名或分组应能直接找到对应任务。 [外观分组](../../frontend/src/components/settings-drawer/SettingsDrawerGlobalAppearanceSection.vue#L113)
- **背景预览和调节控件应形成一个区域。** 当前缩略图只占半栏，右侧留空。1100 × 515 样例进入页面背景时，透明度和模糊在首屏下方。宽布局可让预览与两条竖向排列的滑条并排，窄布局让预览与控件上下相接。亮色的 30% 与 0 px 都是粗灰轨配黑点，暗色是主题色圆点配弱轨，两色都没有走过区间的填充。为背景透明度、模糊和消息行高共用一套细圆轨、主题色填充、带浅芯的环形滑块和右侧等宽数字读数。点击轨道、拖动、键盘调节及预览都要可用，深浅色给滑块一致的可见焦点。 [外观滑条](../../frontend/src/components/settings-drawer/SettingsDrawerGlobalAppearanceSection.vue#L148) · [Material Web 滑条](https://material-web.dev/components/slider/) · [W3C 滑条键位](https://www.w3.org/WAI/ARIA/apg/patterns/slider/)

### API 预设

- **列表宽度先给了隐藏操作。** 1280 px 桌面样例中，长预设的文字盒总宽 125 px，含给行末动作留出的 28 px，实际名称很早截断。列表行是可以点击和拖动的普通元素，键盘可到删除按钮，无法聚焦预设本身。让选择行成为语义按钮，以两行或更宽的可用列显示全名，模型和 TTS 用可读的类型标记，删除放到独立操作。窄布局换成可检索的选择入口或列表进入详情，减少横向滚条和截字叠加。 [预设列表](../../frontend/src/components/settings-drawer/SettingsDrawerPresetsTab.vue#L94)
- **类型和名称各自表达。** 「作为 TTS 服务」藏在预设名称同一行，列表只用小写 t 标记类型。标题处应显示正在编辑的预设及其类型，新建时先选模型服务或语音服务，再显示对应连接字段。将「编辑中的预设」和「当前聊天实际使用的预设」明确区分。

### 当前会话

- **范围说明缺少会话身份和生效值。** 首屏只有「仅对当前会话生效」和长文本框，模型组里的「使用全局」占位不给实际数值，「未启用（使用全局）」也混淆了关闭与继承。头部显示会话名、实际模型和预设。把「沿用全局 · 当前值」「已覆盖」「已关闭」做成能直接辨认的字段状态，并给已有覆盖提供就近恢复入口。 [会话模型表单](../../frontend/src/components/settings-drawer/SettingsDrawerChatTab.vue#L129)
- **高级配置的范围不总是会话。** 正则后处理面板包含共享的规则，单聊调整角色世界书顺序会同步角色卡。将「配置作用范围」标在相关字段或动作旁。默认视图优先模型、提示词和记忆，其余 MVU、世界书、正则和 TTS 在组标题上显示当前状态或数量。 [正则说明](../../frontend/src/components/settings-drawer/SettingsDrawerChatRegexSection.vue#L13) · [世界书保存](../../frontend/src/components/SettingsDrawer.vue#L4040)
